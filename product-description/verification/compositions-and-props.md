# Verification: compositions and props

This file checks six documents against the running product: [the Compositions panel](../compositions/the-compositions-panel.md), [the Omnibar](../compositions/the-omnibar.md), [creating and duplicating](../compositions/creating-and-duplicating.md), [composition settings](../compositions/composition-settings.md), [the Props Editor](../props/the-props-editor.md), and [prop fields](../props/prop-fields.md). Each document has one table; each row is one observable claim.

How to run this file: bring up Studio as [the protocol](README.md#how-to-run-a-pass) describes, on the throwaway copy `verify-examples/` with its four test compositions (Verify Title, Verify Unbound, Verify Media, Verify Vanilla), in a desktop Chromium-based browser at `http://127.0.0.1:5173/`, and make the extra fixtures below. Unless an item says otherwise, start it from the **baseline**: **Fresh** as [foundations.md](foundations.md) defines it (local storage cleared and the page reloaded), then the composition the Setup names opened by clicking its tile, connected (or, for Verify Vanilla, showing "Connection Failed..."), and paused, with keyboard focus on the page and no dialog open. Many items create, rename, move, or delete composition folders: put each fixture back afterwards (keep a pristine copy of each fixture folder beside the copy and copy it back), and reload Studio after any change on disk, because Studio does not watch the project. A switch from a connected composition can carry its input props into the next one and save them there, so after an item that switches, check that the fixtures' `composition.json` files hold no unexpected `defaultProps`. "Paused" means ▶ is shown in the transport controls; "playing" means ❚❚ is shown after pressing Space.

### Fixtures

The protocol's test compositions are used as they are: **Verify Title** (`verify-title`, Title explainer, clock-bound, connects, input props `title` and `subtitle`, no schema; read from the code the Props Editor never auto-saves it), **Verify Unbound** (`verify-unbound`, the same without its document-clock binding, 150 frames at 30 frames per second; its default title is "Verify Unbound"; every item that needs a save to happen uses it or a copy of it), and **Verify Vanilla** (`verify-vanilla`, never connects). Make these as well, on disk, after the protocol's step that removes `defaultProps` from the test compositions:

- **Schema Check.** Copy `verify-unbound` to `schema-check` (with no `defaultProps` in its `composition.json`). In its `composition.html`, insert the block below on the line before `const helios = new Helios(`, and in that line add `, schema: SCHEMA` after `inputProps: defaults`. It draws its `title` prop; read every other prop from the composition (see below). Two variants are separate copies made the same way: **Schema Levels** (`schema-levels`) adds `levels: { type: 'int8array', default: new Int8Array([1, 2, 3]) },` to the block, and **Schema Strict** (`schema-strict`) adds `strict: { type: 'string', optional: true, minLength: 3 },`. Keep the typed array out of Schema Check itself: once it is saved, the composition refuses its own saved props on every later opening (PROPSEDITOR-66).

```js
  title: { type: 'string', label: 'Headline', description: 'The big line', minLength: 2, maxLength: 20, default: 'Hello' },
  code: { type: 'string', pattern: '^[A-Z]+$', default: 'ABC' },
  opacity: { type: 'number', minimum: 0, maximum: 1, default: 1 },
  count: { type: 'number', minimum: 0, maximum: 100, default: 10 },
  size: { type: 'number', minimum: 1, default: 5 },
  titleIn: { type: 'number', format: 'time', minimum: 0, maximum: 8, default: 1 },
  mode: { type: 'string', enum: ['fade', 'slide'], default: 'fade' },
  mixed: { type: 'number', enum: [1, 'two'], default: 1 },
  data: { type: 'json', accept: ['.json'], default: 'data.json' },
  config: { type: 'json', default: '' },
  file: { type: 'string', accept: ['.txt'], default: 'a.txt' },
  day: { type: 'string', format: 'date', default: '2026-01-01' },
  clock: { type: 'string', format: 'time', default: '14:30' },
  tags: { type: 'array', items: { type: 'string', minLength: 1 }, minItems: 1, maxItems: 3, default: ['a'] },
  nums: { type: 'array', items: { type: 'number' }, default: [1] },
  box: { type: 'object', properties: { x: { type: 'number', default: 0 }, label: { type: 'string', optional: true }, at: { type: 'number', format: 'time', default: 2 } }, default: { x: 0 } },
  meta: { type: 'object', default: {} },
  accent: { type: 'color', default: '#ff0000', group: 'Style' },
  visible: { type: 'boolean', default: true, group: 'Style' },
  note: { type: 'string', optional: true },

```

- **Inferred Check.** Copy `verify-unbound` to `inferred-check` (no `defaultProps`) and add these keys to the object on its `const defaults =` line: `"n": 5, "flag": true, "hue": "#ff0000", "items": [1, 2], "obj": {"a": 1}, "nothing": null`. It has no schema, so every prop gets an inferred field.
- **Scenes.** Copy `simple-canvas-animation` to `scenes/intro` and to `scenes/outro/end`, and `verify-unbound` to `scenes/intro-card` (no `defaultProps`). They add a "Scenes" folder to the Compositions panel.
- **Delete Me.** Copy `simple-canvas-animation` to `delete-me`, the composition that delete items act on.

Like the protocol's Verify Media, the schema was written from the source, not run: if Schema Check shows "Error: ..." or never connects, read the browser console and adjust it before using it.

Four other projects are served in place of the copy (stop the copy's server first, so that each is served at the same address):

- **Pristine copy**: `verify-examples-2/`, a second `cp -R examples verify-examples-2` with no test compositions and no fixtures, for the items that count tiles, assets, or names in the verification project as the documents describe it.
- **Empty project**: `verify-empty/`, an empty folder beside the copy. It has no compositions.
- **Root project**: `helios studio` started inside `verify-examples/verify-unbound`, with no `defaultProps` in its `composition.json`. Its `composition.html` is at the project root, so its ID is empty and it is the project's only composition (Studio does not look inside a composition's folder).
- **Bare root project**: started inside `verify-examples/simple-canvas-animation`, which has no `composition.json`.

If a composition does not load in the root projects, mark their items blocked.

### Reading what the composition holds

Most of Schema Check's and Inferred Check's props are not drawn. To read the input props the composition holds, choose the composition's frame as the console's context (or use `document.querySelector('helios-player').shadowRoot.querySelector('iframe').contentWindow.helios`) and evaluate `helios.getState().inputProps`; "read `name`" in a step means reading that prop there. A refused change is reported in that console as an error. To read what Studio saved, open the composition's `composition.json` in the copy. Use the console to observe, never to make a change; every change is made with real input.

### The Device column

The values [the protocol](README.md#devices-and-conditions) defines (`mouse`, `keyboard`, `devtools`, `disk`, `server`, `second tab`, `desktop file`, `clipboard`, `Mac`, `Windows or Linux`) mean the same here. This file adds:

- `throttled`: devtools Network throttling set to "Slow 3G", which delays every request by about two seconds, so that "Creating...", "Saving...", and "Updating..." can be seen and interrupted. It also slows loading the composition; turn it off afterwards.
- `clipboard denied`: the Studio address's clipboard permission set to Block in Chromium's site settings, with known text already on the clipboard.
- `editor`: `helios studio` started with `LAUNCH_EDITOR` naming an installed code editor (for example `LAUNCH_EDITOR=code`). `no editor`: started with no `LAUNCH_EDITOR` and no code editor running.
- `Linux`: a disk that respects case, where the item's result depends on it.

### Which claims have items

Every cell of a document's Modifiers and Cancel and interrupt tables that says more than "No effect" or "Nothing to lose" has an item; a cell that says "Same" is covered by an item that runs the same steps in that phase. Every behavior a document calls a bug, a likely bug, or a suspected bug, or says "may be worth treating as a bug", has a P1 item marked "(suspected bug)" whose expected result is "Record what happens"; the Claim column gives the document's reading of the code. Items marked "(to confirm)" are claims the document itself asks to be confirmed. An item whose Setup depends on something this commit may not do (a delete that reaches the server) says so and is marked blocked when it does not happen.

Not checkable by hand:

- A text or number box taking a new value when the prop is changed elsewhere while the user types, and a JSON box replacing its text mid-typing ([While ongoing](../props/prop-fields.md#while-ongoing), [JSON boxes](../props/prop-fields.md#json-boxes)): the only change that reaches a prop without taking focus from its field is a time-prop marker drag, which changes only time props.
- A refused change reaching the player's error panel for a composition connected through `connectToParent`: the one such example, `client-export-api`, has no schema, so nothing it is given is refused; checking it needs a copy with a schema added.
- A slider being dragged when the pointer leaves the window follows the browser's own rules, not Studio's.
- Whether Studio should show the composition's refusal to the user, and whether asset and color fields should keep partial text, are product calls ([Open questions](../props/prop-fields.md#open-questions-and-verification)).
