# Verification: assets and panels

How to run this file: work in a disposable copy of the verification project (`examples/`), started with `helios studio` from inside the copy as the protocol in `README.md` in this directory describes, in a desktop Chromium-based browser with a fresh profile, because these items rename, move, and delete real folders and every example folder is an asset folder. Leave every preference at its default (sidebar 250 pixels wide, Studio's volume at 100% and unmuted, render settings untouched). Run ASSETPANEL-01 and ASSETPANEL-02 on the untouched copy, then add the fixtures below. Before each table, reload the page and click the table's sidebar tab; between items, put back anything an item renamed, moved, deleted, or made read-only (`chmod u+w`), or start again from a fresh copy where an item's Setup says so. "Restart Studio" means stopping `helios studio` with Ctrl+C in its terminal, starting it again, and reloading the page. The Device column says what an item needs, joined with "+":

- `mouse`: a mouse with a wheel. `keyboard`: a physical keyboard.
- `desktop drag`: files dragged from the operating system's file manager onto the Studio window, with both visible side by side.
- `picker`: the browser's own file chooser, opened by Upload or by the Captions panel's file chooser.
- `disk`: a shell or file manager on the project copy, to prepare files and to read back what is on disk (contents, sizes, permissions).
- `terminal`: the terminal running `helios studio`: reading its output, stopping it with Ctrl+C, and starting it again with extra environment variables.
- `devtools`: Chromium's developer tools: the Network panel's request list, and its throttling (a custom profile of about 10 Mbit/s upload makes `big.mp4` below take 30 to 60 seconds, long enough to interrupt).
- `second tab`: a second Studio tab on the same address, in the same browser window.
- `other app`: another application window, such as a plain text editor, to take focus from the browser or to receive a drop.
- `audio`: speakers or headphones.
- `editor`: a code editor the Studio server can launch: start `helios studio` with `LAUNCH_EDITOR` set to the editor's command (for example `LAUNCH_EDITOR=code`).
- `network`: internet access for the package manager the Studio server runs.
- `registry`: a local static file server (for example `python3 -m http.server 8099` in a folder) serving a component registry.

Fixtures, made with `disk` unless the text says otherwise. Test media can be made with `ffmpeg` or `sox`; real music and speech make the audio items easier to judge by ear.

1. **`vtest/`** in the copy's root, holding: `a-very-long-folder-name-to-wrap/` (empty); `data/data.json` (`{}`), `data/logo.png` (a copy of `images/logo.png`), and `data/a-very-long-file-name-for-the-ellipsis-test.json` (`{}`); `fonts/Fancy.ttf` (a script or blackletter font that looks nothing like the browser's sans-serif) and `fonts/broken.ttf` (a text file renamed); `images/logo.png`, `images/old.png`, `images/photo.jpg`, the empty folders `images/icons/`, `images/icons-old/`, and `images/v1.5/`; `media/clip.mp4` (5 to 10 seconds with visible motion, for example `ffmpeg -f lavfi -i testsrc=duration=8:size=640x360:rate=30 clip.mp4`) and `media/music.mp3` (stereo, at least 20 seconds); `models/box.glb`; `shaders/wave.glsl`; `sort/` with the empty folders `10/`, `2/`, `Zebra/`, `apple/` and the files `A.json`, `a.json`, `b.json` (each `{}`); and `notes.txt`. After these are made, reload the Studio page so the list is read again.
2. **`~/vtest-upload/`**, a folder outside the project, holding: `new.png`, `a.png`, `b.png`, `c.png`; `logo.png` (a picture clearly different from `vtest/images/logo.png`); `notes.txt`; `ロゴ.png` (a PNG with that Japanese name); `data.json` (`{"v": 2}`); `big.mp4` (about 50 MB, for example `head -c 50M /dev/urandom > big.mp4`); `huge.mp4` (1 GB or more, made the same way); `v1/x.png` and `v2/x.png` (two different pictures with the same name); and the caption files of fixture 5.
3. **Asset Props**: a composition made in Studio with New Composition, template Title explainer, name "Asset Props" (folder `asset-props/`). In its `composition.html`, change `inputProps: defaults` in the `new Helios({...})` call to `inputProps: { ...defaults, logo: '', clip: '', meta: { a: 1 } }, schema: { title: { type: 'string' }, subtitle: { type: 'string' }, logo: { type: 'image' }, clip: { type: 'video' } }`, add `import data from './data.json';` after the first `import` line, and create `asset-props/data.json` containing `{}`. The Props Editor then shows text boxes for title and subtitle, asset fields for logo (image) and clip (video), and a JSON box for meta. If it does not connect after the edit, mark the items that use it `blocked`.
4. **Vanilla Test**: a composition made in Studio from the Vanilla JS template. It never connects, so it stands for "before the player connects".
5. **Caption compositions and files.** **Caption Test**: a Title explainer composition, unchanged. **Caption Own**: a Title explainer composition whose `new Helios({...})` options gain `captions: "1\n00:00:01,000 --> 00:00:03,000\nBuilt in"`. **Caption Bridge**: a Title explainer composition in which `window.helios = helios;` is replaced by `connectToParent(helios);`, with `import { connectToParent } from '@helios-project/player/bridge';` added after the first `import` line, and the line `helios.bindToDocumentTimeline();` deleted so that the auto-save can come (if the import cannot be resolved, mark CAPTIONS items that use it `blocked`). The example `client-export-api` connects the same way but is clock-bound, so it shows the panel's behavior without the save. In `~/vtest-upload/`: `good.srt` (two cues: `1`, `00:00:01,000 --> 00:00:02,500`, `First cue`; blank line; `2`, `00:00:03,000 --> 00:00:04,000`, `Second cue`); `onedigit.srt` (as `good.srt` with `0:00:01,000` as its first time); `period.srt` (as `good.srt` with periods before the milliseconds); `mixed.srt` (as `good.srt` with a period only in the second cue's time line); `captions.vtt` (`WEBVTT`, blank line, `00:00:01.000 --> 00:00:02.000`, `Hello`); `blank.srt` (three lines of spaces and blank lines); `empty.srt` (zero bytes); `long.srt` (40 cues, one per second).
6. **Audio Test**: a Title explainer composition named "Audio Test". Into its folder copy `music.mp3` (stereo music, at least 30 seconds), `voice.mp3` (stereo speech, at least 30 seconds), `sfx.mp3` (a third distinct stereo sound, at least 30 seconds), `tone.wav` (`sox -n -r 48000 -c 2 tone.wav synth 30 sine 440 vol 0.5`), `loud.wav` (the same at `vol 1.0`), `square.wav` (`synth 30 square 440 vol 0.9`), `mono.wav` (`-c 1`, sine at `vol 0.5`), and `silent.mp4` (a video with no sound track). In `composition.html`, add `autoSyncAnimations: true` to the `new Helios({...})` options and put these four elements in `<body>` before the script: `<audio data-helios-track-id="music" src="music.mp3" loop></audio>`, `<audio data-helios-track-id="voice" src="voice.mp3" loop></audio>`, `<audio id="sfx" src="sfx.mp3" loop></audio>`, `<audio src="tone.wav" loop></audio>`. The Audio panel should list `music`, `voice`, `sfx`, and `track-3`. Before the AUDIOMIXER items, press Space and confirm the tracks are heard; if nothing is heard at all, mark the items that need `audio` `blocked`. **Audio Two**: a copy of `audio-test/` named `audio-two/` whose `composition.html` keeps only the `music` element; reload the page to list it.
7. **Components copy**: a second disposable copy of `examples/` with a `helios.config.json` at its root containing `{"version": "1.0.0", "directories": {"components": "src/components/helios", "lib": "src/lib"}, "components": []}` and a `package.json` beside it containing `{"private": true}` (without it, npm treats the Helios repository around the copy as the project and installs there; see [the Components panel](../panels/the-components-panel.md#while-ongoing)), started with `helios studio` in place of the first copy, with `network`. The COMPONENTS items say which copy they use; "the plain copy" is the copy without `helios.config.json`.
