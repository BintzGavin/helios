# Verification: stage and output

How to run this file: bring up Studio as [the protocol](README.md#how-to-run-a-pass) describes, on the throwaway copy `verify-examples/` (renders, edits, and renames in these items change files in it), in a desktop Chromium-based browser at `http://127.0.0.1:5173/`, with a window of about 1600 by 900 pixels and the panels at their default sizes. Before each table, clear the site's local storage (developer tools, Application, Local storage, `http://127.0.0.1:5173`, Clear all) and reload, so that the stage view is at 100% and centered, the transparency grid is on, the safe-area guides are off, and the render settings are at their defaults (Canvas mode, nothing else set); then open the composition the row names from the Compositions panel (Studio itself opens Audio Visualization first). Rows about frames use Verify Driveable, because every example and template is a [clock-bound composition](../foundations/the-preview-player.md#clock-bound-compositions) whose frame Studio cannot hold; run the preview player's clock-bound items before this file. Server-side renders and client-side exports take real time, so rows that do not depend on the length set a short range. "Seek to frame N" means: click the timecode field, select all, type N, press Enter. "Set the range to A-B" means: seek to A, click the empty background of the timeline panel below the tracks, press I; seek to B, click the background again, press O. "Read `key`" means: developer tools, Application, Local storage, the value of `helios-studio:key`. "Probe a file" means: run `ffprobe -v error -count_frames -show_entries stream=codec_name,width,height,pix_fmt,r_frame_rate,nb_read_frames,bit_rate,sample_rate,channels {file}` on it.

The Device column says what an item needs beyond the browser: `mouse` (a mouse with a notched wheel; Chromium reports about 100 units per notch; left button unless a step says otherwise), `trackpad` (two-finger scrolling and pinching), `keyboard` (a US English layout), `keyboard layout` (an operating system layout other than US English), `devtools` (Chromium's developer tools: Application storage, the Console to read `document.activeElement`, Network throttling to "Slow 3G" to keep a request in flight for a few seconds and request blocking by URL pattern, the Accessibility pane, and the element inspector to measure sizes), `disk` (an editor or shell on the files in `verify-examples/`, including `ffprobe` from FFmpeg and an image viewer for downloaded files), `server` (the terminal running `helios studio`: stop it with Ctrl+C and start it again with the same command), `second project` (the empty project below), `second tab` (another tab of the same browser at the same address), `second window` (another application's window, to take focus or receive a release), `speakers` (the item is judged by ear), and `Mac` or `Windows or Linux` when an item applies to one platform only. These are the protocol's [devices and conditions](README.md#devices-and-conditions).

Setups named in the Setup column. Verify Vanilla is the protocol's test composition; the others are this file's own and are made in addition to the protocol's:

- **Small view**: Fit, then the stage toolbar's - four times, so that the zoom reads 41% and the checkerboard shows on every side of a 1920 by 1080 composition.
- **Verify Driveable** (`verify-driveable`): made with the header's "+" (New Composition) from the Title explainer template, named "Verify Driveable", 1920 by 1080, 30 frames per second, 10 seconds (300 frames); then the line `helios.bindToDocumentTimeline();` deleted from `verify-driveable/composition.html`, any `defaultProps` deleted from its `composition.json` (creating it is a switch, which can carry another composition's props into it), and the page reloaded. It connects and Studio can hold its frame. Its input props are `title` and `subtitle`; its canvas is drawn at 1920 by 1080 whatever the canvas size.
- **Verify Other** (`verify-other`): made the same way, named "Verify Other", 24 frames per second, 8 seconds (192 frames), bind line deleted. It is not opened before the rows that use it (its timeline state must not be remembered).
- **Verify Vanilla** (`verify-vanilla`): the protocol's, made with "+" from the Vanilla JS template. It never connects: "Loading..." and then, after 5 seconds, "Connection Failed...".
- **Simple Animation** (`simple-animation`): the example drawn with HTML elements and no `<canvas>`. It connects and is clock-bound.
- **Verify Transparent** (`verify-transparent`): `cp -r verify-driveable verify-transparent`, then in its `composition.html` remove `background:#0c1622` and replace `ctx.fillStyle = gradient; ctx.fillRect(0, 0, 1280, 720);` with `ctx.clearRect(0, 0, 1280, 720);`, and reload.
- **Verify Audio** (`verify-audio`): `cp -r verify-driveable verify-audio`, put any MP3 of at least 10 seconds with a change you can hear at 2 seconds (a spoken count works) next to it as `tone.mp3`, add `<audio src="./tone.mp3" data-helios-track-id="tone"></audio>` to the body of its `composition.html`, and reload.
- **A caption**: in the Captions panel, import an SRT file with one cue, `00:00:01,000 --> 00:00:02,000`, "HELLO" (frames 30 to 59 at 30 frames per second).
- **The empty project**: stop the server, start `helios studio` in an empty folder `verify-empty/` beside `verify-examples/` (it serves at the same address and shares every remembered value), and reload; the stage shows "Welcome to Helios Studio". Return by stopping it and starting the server in `verify-examples/` again. Undo any remembered value a row changed there.

Not checkable by hand:

- A capture lasts about two screen refreshes, too short to interrupt by hand, so these cells need a scripted race: a seek or frame step during a capture (the picture changes, the file name keeps the starting frame); a switch, a hot reload, or a reload during a capture (it never finishes, or ends with "Failed to take snapshot", or captures the reloaded page); a hidden tab during a capture (it waits and then finishes); and pausing or seeking during a capture ([Cancel and interrupt](../output/snapshots-and-job-specs.md#cancel-and-interrupt), [Modifiers](../output/snapshots-and-job-specs.md#modifiers), [Open questions](../output/snapshots-and-job-specs.md#open-questions-and-verification)).
- That a snapshot taken while playing shows the frame two screen refreshes after the one in its name: the difference is too small to judge by eye ([While ongoing](../output/snapshots-and-job-specs.md#while-ongoing)).
- The server's own message for a job spec it refuses: there is no known way to make the server refuse one from the page ([Finishing](../output/snapshots-and-job-specs.md#finishing)).
- Running a job spec, and `helios job run` resolving its paths from the job file's folder, are outside Studio and out of scope ([Open questions](../output/snapshots-and-job-specs.md#open-questions-and-verification)).
- Product calls: whether a job spec should carry the input props (SNAPSPEC-26), the Video Bitrate, and the Hardware Acceleration setting (SNAPSPEC-27); whether a job spec with no frames should be refused (SNAPSPEC-37); whether a snapshot with nothing to capture should say so (SNAPSPEC-30) ([Open questions](../output/snapshots-and-job-specs.md#open-questions-and-verification)).
