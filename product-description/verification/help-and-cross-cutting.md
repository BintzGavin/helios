# Verification: help and cross-cutting

How to run this file: bring up Studio as [the protocol](README.md#how-to-run-a-pass) describes, on the throwaway copy `verify-examples/` with the four test compositions made, in a desktop Chromium-based browser at `http://127.0.0.1:5173/`, and use the setups the [foundations checklist](foundations.md) names: **Fresh**, **Unbound**, **Media**, **Title**, **Vanilla**, **Player focused**, "Set the playhead to N", "Set the in point to N", and "Read `key`". Unless an item says otherwise, start it from **Unbound**, with keyboard focus on the page (click the empty background of the timeline panel below the track area) and every dialog closed; close every dialog and reload the page between items. Items whose Device column says `disk` change files in the copy: undo each change after its item, or delete the copy and make it again. The third table (changes from outside Studio) changes the copy the most; run it last in a session. Playback in the expected results (▶ or ❚❚, the timecode advancing, the speed menu) and the Props Editor's auto-save are judged on Unbound or Media, which the transport can drive. Title, Vanilla, and the examples are [clock-bound](../foundations/the-preview-player.md#clock-bound-compositions), and read from the code the [auto-save](../glossary.md#the-preview) never comes for a clock-bound composition, so no item here waits for one on Title.

Setups named here in addition to the foundations checklist's:

- **Empty project**: stop the copy's server, make an empty folder `verify-empty/` beside `verify-examples/`, start `helios studio` in it, and open its address. Studio shows "Welcome to Helios Studio" with no composition open. Stop it and restart the copy's server afterward.
- **Component config**: a `helios.config.json` at the root of the copy containing `{"version": "1.0.0", "directories": {"components": "src/components/helios", "lib": "src/lib"}, "components": []}`, and a `package.json` beside it containing `{"private": true}`, with `helios studio` restarted after adding them. Without the configuration nothing can be installed. Installing runs `npm install` and needs the network; without the `package.json`, npm would treat the Helios repository around the copy as the project and change its root `package.json` and lockfile (see [the Components panel](../panels/the-components-panel.md#while-ongoing)).
- **Prompt for "X"**: in the Helios Assistant's Ask AI tab, click into the question box, select all, type X, and press Enter.

The Device column uses the values of the protocol's [devices and conditions](README.md#devices-and-conditions), with these additions and details:

- `server` here also means a process list (`ps aux | grep -i chrom`, Activity Monitor, or Task Manager) beside the terminal, to watch the headless Chromium the Studio server starts for each System Diagnostics check. The terminal prints "[RenderManager] Running server diagnostics..." once per check.
- `agent`: as the protocol says, an MCP client on the same computer connected to `http://127.0.0.1:5173/mcp`, over Streamable HTTP. Studio refuses a client on another computer and a request whose `Origin` header is not Studio's own address. The tools used here are `list_compositions`, `create_composition`, `render_composition`, `get_render_output`, `cancel_render`, `install_component`, and `uninstall_component`; the resources are `helios://documentation`, `helios://assets`, `helios://components`, and `helios://compositions`.
- `no Chromium`: `helios studio` started with the environment variable `PLAYWRIGHT_BROWSERS_PATH` set to a new empty folder outside the copy, so the server finds no headless browser and the first check downloads one into that folder (this needs the network; delete the folder afterward). With `HELIOS_SKIP_BROWSER_DOWNLOAD=1` set as well, the launch fails instead of downloading.
- `repo root`: `helios studio` started in the root of the Helios repository itself (`/home/user/helios`), after stopping the copy's server. Use it only to read the Documentation tab; change nothing there.

Not checkable by hand:

- Whether a second `helios studio` on the same project should be refused (a product call; [Open questions](../cross-cutting/changes-from-outside-studio.md#open-questions-and-verification)).
- Whether open tabs should follow each other's remembered values (a product call; [Open questions](../cross-cutting/changes-from-outside-studio.md#open-questions-and-verification)).
- Whether two tabs' auto-saves should be reconciled or warned about (a product call; [Open questions](../cross-cutting/changes-from-outside-studio.md#open-questions-and-verification)).
- Whether an agent cancelling the user's render should be announced in Studio (a product call; [Open questions](../cross-cutting/changes-from-outside-studio.md#open-questions-and-verification)).
- That an agent cannot read or change the remembered values: an absence of capability (no tool of Studio's MCP server touches browser storage), not an observation ([Interactions with other systems](../cross-cutting/changes-from-outside-studio.md#interactions-with-other-systems)).
- That Studio does not lock files, compare versions, or detect conflicts, and offers no undo for an outside edit it writes over: design properties whose individual consequences are OUTSIDE-14, OUTSIDE-15, and OUTSIDE-32 ([Interactions with other systems](../cross-cutting/changes-from-outside-studio.md#interactions-with-other-systems)).
