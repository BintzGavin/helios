✨ RENDERER: Remove redundant dynamic progress counter math in single-worker fast paths

💡 What:
Removed the dynamic progress counter (`progressCounter -= ...`) logic from the single-worker capture loops (DOM and Canvas paths) in CaptureLoop.ts. It now calculates bounds using `progressInterval` directly.

🎯 Why:
To eliminate loop-carried variable mutations and conditional branch evaluations in the AST inside V8's hot path (PERF-1182).

📊 Impact:
- Best render time: 8.700s (vs baseline 8.720s)
- Improvement: ~0.23%

- Canvas smoke tests ran correctly
