# PERF-1100: Inline Multi-Worker `isDomStrategy` loops

## Focus Area
The multi-worker writer chunk loops inside `packages/renderer/src/core/CaptureLoop.ts`.

## Background Research
Presently, multi-worker chunk writers separate branch logic via `if (isDomStrategy)` loops:
```typescript
        if (isDomStrategy) {
// loop
        } else {
// copy loop
        }
```
This is because `domLastFrameBuffer` buffers identical frame frames, and canvas strategies inherently return standard promises/frames. However, this duplicates loop iteration instructions over many bytes, harming JIT compilation by making the AST too complex (exceeding optimization thresholds), leading to slower V8 execution in Node.js. Given V8 handles monomorphic type optimization exceptionally well in inner loops, combining the buffer logic conditionally enables a much tighter loop boundary.

Instead of separating the `while` loops, we can combine them, maintaining the specific logic internally but significantly reducing code redundancy. In multi-worker scenarios, we duplicate chunk writing inside `try { let nextProgress ... if (isDomStrategy) { while(..) { ... } } else { while(..) { ... } }`. We can fold this writer loop together since it functionally does exactly the same process (extracting buffer and passing to `stream.write`).

## Benchmark Configuration
- **Composition URL**: standard DOM benchmark
- **Render Settings**: 1080p, 60fps, 5 seconds
- **Mode**: `dom`
- **Metric**: Wall-clock render time in seconds
- **Minimum runs**: 3 per experiment, report median

## Baseline
- **Bottleneck analysis**: The capture loop AST is extremely large. The multi-worker mode has duplicate logic blocks for strategy types inside the `isDomStrategy` branches, which is unnecessary since standard canvas captures return promises identical to `isDomStrategy`'s requirement with small tweaks.

## Implementation Spec

### Step 1: Fold Multi-worker Writer Chunk Loops
**File**: `packages/renderer/src/core/CaptureLoop.ts`
**What to change**:
In `CaptureLoop.ts` starting at the `try { let nextProgress = progressInterval; ...` block for the multi-worker writer loops (around line 551), there is a large `if (isDomStrategy) { if (nextFrameToWrite < totalFrames && !aborted) { while(...) ... } } else { if (nextFrameToWrite < totalFrames && !aborted) { while(...) ... } }`.

These blocks are practically identical. Since both `buffer` references are implicitly identical at runtime (buffers), we can remove the `if (isDomStrategy) {} else {}` envelope completely.
